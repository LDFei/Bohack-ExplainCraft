# 引导制作闭环：设计、落地与验证

日期：2026-11-14。适用目录：Tauri 工作台 `front/` 与 Rust 业务后端 `src-tauri/`。

## 目标与根因

本轮把“主题输入后逐步共同制作”作为产品协议，不依赖模型临时理解一句“每步让我选”。

| 原问题                 | 根因                                                                                  | 当前落地                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 素材库上传失败         | Tauri 原始 IPC 将 Content-Type 改为 application/octet-stream，multipart boundary 丢失 | 单独传递并验证 X-Upload-Content-Type；恢复 multipart 后解析，失败清理新文件 |
| 聊天没有选择反馈       | 原后端默认全自动；前端忽略 question.input_type/options；没有真实应用内 skill 加载机制 | 十二步规则清单、Markdown 约束、后端确认状态、前端选项卡                     |
| 固定秒数控件与对话冲突 | 输入框设置、文本解析与模型策划可分别覆盖时长                                          | 移除输入框秒数控件；在对话确认时长；模型只可建议自动模式                    |
| 新建 / 结束话题不可靠  | 同一路由导航未清理临时输入；缺少明确结束入口                                          | 新建清空临时创作入口；结束先请求取消活动任务，历史仍可访问                  |
| 制作过程反馈弱         | 只有粗粒度阶段更新，终端操作信息未持久化给页面                                        | Job.logs 保存真实操作、镜头编号、耗时及降级原因，在步骤内显示               |
| 剪辑库自动运行         | 预览、导出与剪辑耦合                                                                  | FFmpeg 先输出基础成片；用户明确选择 Quercus 后才调用剪辑库                  |
| 配音缺少选择与兜底     | 配音来源依赖全局配置，没有每次任务选择和统一期限                                      | API / Breeze / BGM 三选一；缺模型询问下载；超时持久化回退 BGM               |
| 模板和规则冲突         | 模板预置时长、配乐和自动执行要求                                                      | 模板只建议叙事与运动语言，全部服从当前任务已确认答案                        |

此前仓库只有注释引用 `.claude/skills/vibe-knowledge-awards`，没有对应规则文件和执行入口。
本次新增的是应用自身的 `src-tauri/skills/`，不依赖 Codex / Claude 客户端是否安装个人技能。
这些规则随程序编译打包；修改规则后需要重新构建后端。

## 调研依据与选型

[LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
描述了保存状态、暂停并由外部输入恢复的交互方式。
[Temporal Workflow 消息处理](https://docs.temporal.io/develop/typescript/workflows/message-passing)
提供了把输入验证和状态变更作为工作流消息处理的设计参考。
本项目采用这些成熟做法中的持久化确认、幂等处理和明确恢复边界，继续使用现有 SQLite、事件记录与 worker。
没有额外部署 LangGraph / Temporal，也没有引入桌面单用户场景暂时不需要的独立队列服务。

这是一套可执行的工程设计，不代表已经完成企业生产环境的容量、权限、多租户或安全认证验收。
现有鉴权、跨平台和播放地址续期的限制仍需分别验收。

## 十二步协议

规则清单：`src-tauri/skills/manifest.json`；运行入口：`src-tauri/src/skills.rs`、`pipeline.rs`。

| 步骤       | 用户选择 / 确认                                 | 执行边界                                        |
| ---------- | ----------------------------------------------- | ----------------------------------------------- |
| style      | 温暖手绘、极简信息图、电影叙事、高能卡点        | 先确认风格                                      |
| duration   | 15 / 30 / 60 / 120 秒、根据内容推荐、原话指定值 | 指定值支持 15～300 秒；自动推荐在方案中再次展示 |
| visual     | SVG 或 HTML                                     | 决定真实镜头生成与本地输出方式                  |
| voice      | API、breezeTTS2、纯 BGM                         | 不默认替用户选择 API 或下载模型                 |
| music      | 程序化 BGM、上传音频、不配乐                    | 纯 BGM 时不能再选无音乐；Vibe 另提供可选示例曲  |
| plan       | 查看方案、时长、风格、画面后确认                | 才开始写文案                                    |
| script     | 查看文案后确认                                  | 才开始分镜                                      |
| storyboard | 查看分镜后确认                                  | 不立即消耗画面 / 配音调用                       |
| production | 确认开始制作                                    | 并行生成镜头与音频                              |
| render     | 确认输出初版                                    | FFmpeg 合成基础视频、旁白 / 音乐和字幕          |
| post_edit  | 保留初版，或使用 Quercus                        | 已有可播放初版后才可授权剪辑                    |
| delivery   | 确认交付                                        | 释放项目活动任务，不再次渲染                    |

Breeze 安装与上传音乐的缺失项使用额外问题，保留当前主步骤编号。
方案、文案、分镜阶段展示实际产物供确认；需要改写时可结束本轮，再基于保留草稿提交修改。
仅讨论模式仍用于聊天，不会绕过上述步骤直接生成视频。

## 状态、恢复与一致性

1. 问题、任务状态、项目状态和事件在同一 SQLite 事务内提交；等待输入时不占执行 worker。
2. 问题 ID 包含任务 ID；提交必须匹配当前未过期问题，单选值必须属于当前选项。
3. 回答接口使用幂等键；重复请求不重复推进，旧问题返回 QUESTION_NOT_ACTIVE；对话回显中文选项标签，审计仍保存稳定选项值。
4. 任务保留已确认回答和每阶段检查点；刷新、重启从同一问题或检查点恢复。
5. 每次 worker 执行持有 attempt fencing token；取消、旧执行器的迟到结果不能发布。
6. 任务保存语义版本与完整规则 / 镜头配方的 SHA-256 摘要。内容变更后旧任务明确报 SKILL_VERSION_CHANGED，要求重新发起，不暗中替换规则；失败重试同样保留原版本。
7. API 与本地配音使用共同的超时包装；取消和超时分别处理。超时持久化 voice_fallback，恢复后不重发该轮旁白。
8. 配音复用指纹包含来源、文本、声线、语速、语言与时长；换来源不会错误复用旧旁白。
9. 初版发布后任务仍 waiting_input，原片保留。剪辑生成新版本，交付确认恢复时不重复剪辑。
10. jobs.logs 通过增量数据库迁移添加，旧项目与旧草稿字段提供兼容默认值。

上传支持中文文件名、幂等重传、归属验证与类型识别。
等待选择期间可补传素材；执行中拒绝上传，并在提交前重查状态，防止上传和任务启动竞态。
失败写库不会留下本次新上传的孤立文件。

## 渲染、配音与进度

SVG 使用现有 resvg / SMIL 定帧路径。HTML 使用系统 Node.js 24+、Chrome 与 FFmpeg：
拒绝模型脚本、事件、外链和本机文件访问，浏览器禁网，以可信驱动推进 CSS / SMIL 时间。
单镜头最长 60 秒，12fps 采样、30fps 输出，最多 720 张采样帧；同时最多两个浏览器。
进程具有期限，取消、失败和成功均清理本次临时目录与子进程。

基础 DirectRenderer 负责硬切排列、透明字幕图层、全部旁白混音、BGM 循环和 MP4 输出。
它不会运行 Quercus、模型剪辑工具，也不会暗中应用可选转场。
用户选择后续剪辑后，Quercus 使用确认的时间线保存第二版；既有调色适配限制仍存在，不能承诺专业调色已完成。
请求包含工程文件的导出是单独的显式操作，可调用 Quercus 导出 OVE / OTIO / FCPXML。

配音 API 默认期限 45 秒，本地默认 90 秒，可用 VOICE_TIMEOUT_SECONDS 设为 1～600 秒。
超时停止后续旁白，丢弃本轮未完整的新旁白，保留字幕并继续 BGM；没有音乐时生成本地 BGM。
服务返回配置错误 / 明确失败时展示错误，不把所有失败都当超时。
Breeze 参考音配置按合成请求延迟校验，缺参考音时仍能启动应用、打开设置和选择 BGM。
Breeze 模型缺失时先打开设置，用户再次点击“同意并下载”才下载约 5.2GB 的模型；
文件存在不代表 ComfyUI、节点和参考音一定可用。

页面步骤内的日志来自后端真实操作，包含开始、完成、耗时、镜头进度及警告，最多保存最近 200 条。
页面不直接展示原始终端流、API 请求头、密钥、供应商原始响应或本机个人路径。

## 本轮验收与边界

后端使用真实业务 Router、SQLite、Runner 和 FFmpeg，模型部分用确定性替身，避免验证时产生未预期费用。
浏览器检查使用真实 Vue 页面，替换 IPC 返回来隔离前端交互；它不等同于全供应商联网桌面测试。

- Rust：56 项通过，1 项付费供应商生成测试保留为忽略。
- 上传：真实 Tauri
  MockRuntime 原始字节请求、被覆盖的 Content-Type、中文文件名、幂等重传、跨用户 404、等待输入可上传、执行中 409。
- 工作流：逐步确认、非法选项 422、数据库重开恢复、无提前调用、初版前不剪辑、明确同意后恰好一份新版本、交付不重渲染。
- 配音：缺模型不自动下载；假装“就绪”仍重查；真实本机 HTTP API 超时后回退 BGM 并完成视频；通用本地 /
  API 期限包装。
- 媒体：真实 SVG 动画与 HTML / CSS
  / 内联 SVG 动画输出；用 ffprobe 检查规格并提取前后帧确认动画变化；旁白、BGM、字幕与导出。
- 浏览器：选项与确认、旧答案隔离、移除固定秒数控件、后端步骤日志、结束取消、新建清空、Shotcraft 模板入口与真实预览图片加载、上传音频选项不误触发 Breeze 检查。
- 前端：格式检查、TypeScript 检查与正式构建。
- 桌面：cargo check 全目标通过，cargo build 本地可执行文件构建通过。

本轮未下载或运行真实 Breeze 大模型，未发起付费 API 生成；Windows / Linux 的这套新链路没有实机验收。
已有 FFmpeg / Quercus 构建警告和登录、下载地址续期等历史限制不在本轮修复范围。

## 本地启动与复验

关闭旧桌面窗口后，从 front/ 启动，确保重新加载 Rust 后端和打包规则：

```bash
npm run desktop:dev
```

仅刷新旧窗口不能更新 Rust 实现。无需清空应用数据库；旧版本继续保留。
升级前处于进行中的旧规则任务若提示版本已变，结束该话题后重新发起。

检查命令：

```bash
# 在 front/ 执行
npm run format:check
npm test
npm run build
npm run test:workflow-ui

# 在仓库根目录执行
cargo fmt --all --check
cargo test --locked --workspace -j 1
cargo check --locked --workspace --all-targets -j 1
```

浏览器检查使用本机 Chrome，单独启动临时 Vite 端口，不占用正在运行的工作台端口。
HTML 实际输出同样需要本机 Chrome；缺失时可选择 SVG。
