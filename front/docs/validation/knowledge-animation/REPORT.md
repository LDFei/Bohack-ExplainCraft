## 3. 第五步音乐闭环

流程为：确认本地来源 → 当前 music_asset 问题 → 选择已有上传音频或上传新音频 → 自动刷新素材 → 原生音频试听 → 确认具体音频 → 同一任务继续第六步。

前后端均只接受本项目 ready 且时长大于零的 upload 音频；服务端进一步检查实际文件。新上传音频不需要等待重新发布问题候选，当前有效问题可以实时接受，避免旧列表拒绝可见音频。服务端仍拒绝错误归属、来源、状态及过期问题。

上传失败、空列表和取消选择器都保留原问题及返回出口。离开卡片、收起试听或切换问题停止播放。AI 音乐缺配置允许改选；音乐失败卡也补齐返回与无音乐选项。重启恢复依赖同一持久任务与答案，不新建创作窗口。

## 5. 语义动画协议、路由和 CreativeBrief

`scene_plan`
包含 objective、visual_concept、entities、relationships、按时间排序的 events、final_state、style、aspect_ratio、claims，补充受控 palette 和数值 sample_from。

事件由对象 ID、action、start_ms、duration_ms、to 状态和 reasoning 组成。动作支持移动/流动、路径绘制、图表追踪、缩放、显隐、连接及数值/文字切换；拆分合并通过多个对象的显隐与移动组合。时间、对象引用、几何范围、原语和数量受本地校验约束。

普通主题：语义计划 → 本地校验/检查点 → 模型生成受限实体 SVG path 代码与色板 → 本地编译统一动画 →
SVG 或离线 HTML 输出。**第二阶段不再接管事实数字、整片画布和时间轴**，避免自由 SVG 重新发明数据和构图。矢量代码仍由现有模型生成，无第二个更强模型或扩散视频模型。

可计算 search 保留本地真实轨迹，并校验范围。states 仅在明确的文字状态展示兼容标志下使用。普通主题的文字变化数量再多也不会自动选中它。Shotcraft 的显式模板保留原路径。

计划与成功镜头及时保存。单镜头最多追加一次修复，计划已修复时不再给代码第二次修复额度；失败明确记录编译兜底或固定卡片降级。模型调用记录保留生成源码证据，便于不付费重放诊断。

CreativeBrief 存入草稿，保存原始需求、修改记录、确认答案、实际设置、声音要求、素材引用；后续模型上下文持续携带。原始文字完整保留重点、禁忌、指定图形和风格，不由固定模板摘要替代。计划与创作约束指纹绑定，旧计划不能覆盖新修改。

## 6. 与旧文字卡相比的实际提升

同一个编译器组合 path、ellipse、particles、plot、bars、vector、number、text、rect。具备复合矢量轮廓、固定种子粒子运动、带坐标轴与实际点集的曲线/柱图、轨迹绘制、消息流、围绕对象中心的缩放、状态文字更新、数据绑定的实时数字、前后绘制层次和按画幅重排。

概率图和数字引用同一数据点与时间轴，避免独立插值伪造统计。匀加速度位移可明确用 accelerate（二次时间）控制，速度曲线依据给定数据。中文及上标单位使用系统字体补全。色板保留用户方向并提高低对比度标签的可读性。

受控原语尚不等价于任意动画语言：任意路径拓扑变形、复杂物理仿真和自动镜头导演仍受限。没有放开任意 JS、网络、CDN 字体、本地文件访问；离线 Chrome 同时最多一个，SVG 渲染同时最多两个。
