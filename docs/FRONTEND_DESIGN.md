# 视频生成软件：Vue 前端页面与交互设计

版本：v0.1 设计稿 · 日期：2026-11-13

设计目标：第一次使用的人只要输入一句话就能开始，制作过程中看得懂进度，拿到视频后能继续用自然语言修改。首版采用一个工作台，脚本、素材、音频等功能放在这个页面内展开。

配套接口见 [API.md](./API.md)。目前已按本方案实现 Vue 前端演示，启动与功能范围见 [README.md](../README.md)；真实生成后端尚未接通。演示版使用内置示例素材，且只提供真实可用的 720p 导出。

## 1. 整体布局

桌面端采用“历史项目 + 对话 + 作品面板”的三栏布局，整体像 AI 对话工具，右侧增加视频工作区。

```text
┌──────────────┬───────────────────────────────┬────────────────────────┐
│ 产品标识      │ 咖啡店宣传视频       制作中     │ 作品预览      v2 ▾      │
│              ├───────────────────────────────┤                        │
│ ＋ 新建创作   │                               │     ┌──────────┐       │
│              │ 你：做一个温暖治愈的咖啡店短片 │     │          │       │
│ 搜索历史      │                               │     │ 竖屏视频 │       │
│              │ AI：按 30 秒竖屏为你制作……    │     │  播放器  │       │
│ 今天         │ ┌───────────────────────────┐ │     │          │       │
│ • 咖啡店宣传  │ │ 创作方案：温暖 / 店铺宣传   │ │     └──────────┘       │
│ • 旅行短片    │ │ ✓ 脚本和分镜              │ │   播放 / 时长 / 全屏   │
│              │ │ ◉ 素材与配音准备中         │ ├────────────────────────┤
│ 昨天         │ │ ○ 剪辑、效果和成片         │ │ 脚本  素材  音频  设置 │
│ • 产品介绍    │ └───────────────────────────┘ │ │                        │
│              │                               │ │ 镜头 1 · 0—5 秒        │
│              │ AI：完成后可以继续告诉我怎么改 │ │ 画面：咖啡店的清晨……   │
│              │                               │ │ 旁白：从一杯咖啡开始…  │
│              ├───────────────────────────────┤ │                        │
│ 账户 / 设置  │ 📎 说说你想做什么视频……       │ ├────────────────────────┤
│              │ 30秒 ▾  竖屏 ▾  风格 ▾   发送 │ │ 下载预览     导出视频  │
└──────────────┴───────────────────────────────┴────────────────────────┘
```

建议尺寸：左栏 224～248px，中栏自适应，右栏 360～420px。对话内容保持适度行宽，输入框固定在中栏底部。窗口不足 1200px 时，右栏改为可开关抽屉；不足 768px 时使用单栏，历史项目从左侧抽屉打开，“对话 / 作品”在顶部切换。抽屉内使用独立滚动，不把底部发送和导出按钮挤出屏幕。

## 2. 左侧：项目与历史记录

“新建创作”固定在顶部，下面按今天、昨天、更早排列项目。每项显示标题和简短状态，例如“正在生成”“等待补充”“已完成”。点击项目时恢复聊天、当前草稿、生成任务和成片版本。

历史列表支持改名与删除；生成中的项目需要先停止再删除。搜索先对已加载标题做本地过滤，输入框提示“筛选已加载项目”，列表底部提供“加载更多”；全量服务端搜索留到后续，避免界面承诺接口没有的能力。账户区固定底部。

新建入口先清空本地工作台，在用户首次发送时再创建后端项目，避免产生大量空白历史记录。首次上传附件同样需要先创建项目，并复用这个 project_id 继续创作。

## 3. 中间：对话是主操作入口

### 3.1 尚未开始时

页面中心显示“你想做一个什么视频？”，输入框提示：

> 例如：给我的咖啡店做一个 30 秒宣传视频，温暖一点。

下面提供三四个可点击示例：“店铺宣传”“产品介绍”“知识讲解”“旅行记录”。点击只填入可编辑的完整示例句子，不直接启动生成。

首屏只显示附件、时长、画面比例和风格。默认参数来自 capabilities；音色、字幕、调色和特效放到右侧设置中，用户不必先理解专业概念。

### 3.2 发起后

用户消息保留原话和附件缩略图，AI 回复由文本和结构化卡片组成：

| 卡片 | 主要内容 | 操作 |
| --- | --- | --- |
| 创作方案 | 主题、目标时长、比例、风格的简短摘要 | 查看详情 |
| 制作进度 | 脚本分镜、素材、音频、剪辑、效果和输出 | 展开步骤、停止 |
| 待补充问题 | 一句话问题、选项或文本框 | 提交并继续 |
| 成片结果 | 视频封面、版本、实际时长 | 播放、下载、继续修改 |
| 失败说明 | 哪一步失败、可读原因 | 可重试时重试，或修改需求 |

界面可以把接口的 `script/storyboard` 合并显示为“脚本和分镜”，把 `finishing/render` 合并显示为“画面效果与输出”；展开后展示细分阶段。素材和音频同时运行时，两项都显示运行状态。

进度没有可靠百分比时，显示“正在生成配音”等步骤说明与加载状态。不要用定时器编一个持续上涨的百分比，也不把后台估计时间显示成保证完成时间。

### 3.3 输入框与模式

输入框支持多行，Enter 发送、Shift+Enter 换行；中文输入法正在选字时 Enter 不发送。上传或解析中的附件显示独立状态，全部 ready 后才能提交包含这些附件的请求。

默认主按钮：首次为“生成视频”；有成功成片后为“修改视频”。二者分别对应 `intent=generate/revise`。用户点击“仅讨论”后切到 `intent=chat`，明确只进行问答；问答结束不自动生成视频。

生成过程中输入框可以保留下一条草稿，发送按钮暂时不可用，并提供“停止生成”；停止后显示“正在停止”，收到终态才恢复发送。需要补充信息时，在问题卡片回答，避免误开第二个任务。

有本地未保存的表单修改时，发送前先保存草稿，再携带返回的 revision 发消息；如果保存失败，保留本地输入并停止后续提交。自然语言中的新要求可以覆盖原有草稿设置；同一次要求内部有明显冲突时，由后端只针对冲突提问。

生成完成后输入框提示：“哪里想调整？例如：第二个镜头换成咖啡特写，配音慢一点。”让用户直接通过对话修改，不要求先学习时间轴剪辑。

## 4. 右侧：作品预览与可选细调

### 4.1 上半部分：播放器

播放器始终保留作品区域，支持横屏、竖屏和方形比例。视频按可用空间 contain 展示；竖屏预览限制高度，避免把右侧设置完全挤出视口。

- 没有成片：显示画面占位、当前制作阶段，不展示无效播放按钮。
- 第一版生成中：显示脚本或素材准备状态。
- 新版本生成中：保留上一版可播放视频，标记“正在制作新版本”。
- 生成失败：保留旧版播放器，失败原因显示在对话卡片中。
- 草稿修改后：显示“有修改尚未生成”，并提供“更新视频”。
- 查看历史版本：清楚显示“正在查看 v1”；编辑标签页展示该版本快照并只读，提供“回到当前草稿”入口。
- 点击“回到当前草稿”或“基于最新版修改”时，明确切回最新版本和当前 Draft，再允许编辑或发送 revise。查看旧版时不把它作为最新版本的修改基底。

播放器地址过期时重新取版本详情，尽量恢复原播放位置。新版本产生后自动切到新版，但用户主动播放历史版期间先提示“新版本已完成”，由用户点击切换。

### 4.2 下半部分：四个标签页

| 标签 | 首版内容 | 交互原则 |
| --- | --- | --- |
| 脚本 | 完整解说词、分镜卡片、镜头时长、画面说明、旁白 | 默认阅读；点击编辑后统一保存 |
| 素材 | 上传文件、已选镜头素材、来源和处理状态 | 添加附件；通过对话指定替换镜头 |
| 音频 | 音色、语速、背景音乐、旁白及音乐音量 | 使用已接通的示例音色或音乐试听 |
| 设置 | 目标时长、比例、风格、字幕、调色和特效 | 提供简单预设，选项来自 capabilities |

脚本和分镜编辑只保留一处未保存编辑：编辑完整解说词时先保存或放弃，才能编辑分镜旁白。完整脚本变更后提示“分镜会在下次生成时更新”，与 API 的失效阶段规则一致。

表单保存与视频生成分开：点击“保存设置”只保存草稿，旁边显示“生成后生效”；再点击“更新视频”才创建任务。也支持用户直接在输入框描述修改，后端更新草稿并生成新版本。

音乐提供“自动匹配”“无背景音乐”和已接通曲库项。配音预览只播放 capabilities 提供的 sample_url，缺失时隐藏试听；首版不承诺输入任意文字即时试听 TTS，这需要另增接口。

用户自带的音乐可以作为附件发送，并在对话中指定用途；后端在音频阶段处理，草稿记录 music_mode=upload 与对应 music_asset_id。也可在音频标签内选择本项目已就绪的音频，保存为 upload 模式；曲库项保存为 library 模式。

### 4.3 导出操作

底部固定“下载预览”和“导出视频”。无成片时禁用；正在查看历史版本时，导出明确对应当前查看的版本。

点击导出打开小弹窗，选择实际支持的分辨率和格式，再提交导出任务。已有相同规格时直接提供下载；正在导出时显示状态。任务完成后显示明确的“下载文件”按钮，避免长任务结束时浏览器拦截自动弹窗或下载。下载开始失败或链接过期时可以重新获取链接。

## 5. 视觉风格

建议第一版采用浅色工作台：浅灰背景、白色对话和面板、单一紫蓝色主色。布局克制，主视觉来自用户生成的视频。

| 元素 | 建议 |
| --- | --- |
| 页面背景 | `#F7F8FC` |
| 内容面板 | `#FFFFFF` |
| 主按钮 / 当前步骤 | `#6554E8` |
| 主文字 / 次文字 | `#202331` / `#727889` |
| 分割线 | `#E6E8F0` |
| 成功 / 警告 / 错误 | 绿色 / 琥珀色 / 红色，并配文字和图标 |
| 字体 | 系统中文无衬线字体，正文 14～16px |
| 卡片 | 12～16px 圆角，细边框，少量阴影 |

状态不能只靠颜色表达。按钮需要键盘焦点，图标按钮有可读标签；动态进度用礼貌播报，不逐字朗读 AI 流式文本。动画保持轻量，尊重系统减少动态效果设置。

用户界面使用“准备画面”“生成配音”“导出视频”等表达，不显示模型编号、任务队列名或供应商错误堆栈。

## 6. Vue 实现划分

建议采用 Vue 3 + TypeScript。状态集中管理当前项目、消息、任务、Draft、版本和本地未发送输入；路由仅保留创作页 `/create` 与项目页 `/projects/:project_id`。是否使用 Pinia 取决于工程现有约定，接口不绑定某个前端库。

| 页面部件 | 责任 | 主要接口 |
| --- | --- | --- |
| WorkspaceLayout / HistorySidebar | 三栏、抽屉、历史、改名、删除 | projects 列表与管理 |
| ChatPanel / MessageList | 文本、卡片、分页、流式输出 | messages、events |
| Composer | 输入、附件、模式、发送、停止 | assets、messages、cancel |
| GenerationProgress / QuestionCard | 阶段进度、补充信息、重试 | jobs、answers、retry |
| PreviewPanel / VersionSelector | 播放、版本列表、历史快照 | versions |
| ScriptTab / AssetsTab / AudioTab / SettingsTab | 详情与可选编辑 | draft、assets、capabilities |
| ExportDialog | 导出规格、状态、下载 | exports、jobs、download |

事件连接集中管理，每个打开的工作台只保持一个项目订阅。切换路由先结束旧连接；旧项目请求迟到时用 project_id 和请求序号拦截，不能覆盖新项目的画面。快照刷新与事件重连按 API 的一致性规则串行处理。

滚动行为：用户靠近对话底部时随新消息滚动；正在阅读上文时保持位置，提供“有新内容”按钮。消息按 message_id 去重，POST 的乐观消息与后端落库消息用客户端请求 key 关联，避免出现两条相同需求。

## 7. 首版边界与开发顺序

先完成“新建对话 → 发送一句话 → 进度 → 视频预览 → 对话修改 → 下载”的完整闭环，再补脚本编辑、素材管理和音频细调。即使首版先用假数据开发页面，也应覆盖排队、追问、失败、取消、断线恢复和旧版本保留这些状态。

第一版不需要多轨时间轴、任意拖拽剪辑、关键帧或复杂调色面板；用户已经可以通过对话和预设完成主要操作。未来需要高级编辑时，复用现有的草稿、素材和成片版本数据扩展。

页面验收重点：没有素材也能发起；上传中不会误提交；生成时离开再回来可恢复；失败原因可读；停止后不会突然出现迟到成片；改设置后不会误以为已更新；新版本失败仍能看旧版；历史版和当前草稿不会混用；手机端能完成生成、修改与下载。当前已提供自动化浏览器检查，具体执行范围见 [VALIDATION.md](./VALIDATION.md)；真实 Rust 接口与生成供应商仍需后续联调。
